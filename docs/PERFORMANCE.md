# نتائج اختبار الأداء والضغط

> منهجية: سكربت خفيف بلا اعتماديات خارجية (`server/scripts/load-test.js`) يقيس p50/p95/p99 وRPS ومعدل الأخطاء.
> كل نتيجة تُوثق مع: البيئة، نسخة الكود (commit)، حجم البيانات، مستوى التوازي، ومدة الاختبار.

## الإصدار المرجعي 1 — الإنتاج (Railway)

| البند | القيمة |
|---|---|
| البيئة | Railway production (`hr-gov-web-production.up.railway.app`) |
| نسخة الكود | انظر حقل `version` في `/api/health` وقت التشغيل (commit SHA) |
| حجم البيانات | قاعدة seed التجريبية (موظفون ~12، حسابات مستخدمين) |
| نتيجة /api/health | انظر JSON التالي — يُحدَّث عند كل جولة |

```json
{
  "target": "https://hr-gov-web-production.up.railway.app/api/health",
  "requests": 100,
  "concurrency": 5,
  "durationMs": 10669,
  "rps": 9.37,
  "p50_ms": 399,
  "p95_ms": 1388,
  "p99_ms": 1750,
  "errors": 0,
  "statuses": { "200": 100 }
}
```

> ملاحظة: RPS منخفض لأن الطلبات من عميل واحد خارج المنطقة (network-bound)؛ هذه قاعدة مرجعية للشبكة العامة وليست سقف قدرة الخادم.

### كيفية إعادة التشغيل
```bash
# صحة عامة (قراءة فقط)
node server/scripts/load-test.js https://<host> /api/health 100 5

# مسار محمي: صدّر كوكي الجلسة إلى ملف session.txt أولاً ثم:
node server/scripts/load-test.js https://<host> "/api/hr/employees?limit=50" 200 5 session.txt
```

### القيود الحالية (معلومة صريحة، لا ادعاء)
- لم تُقس مسارات حساب الرواتب تحت حمل بعد (تتطلب بيانات اصطناعية بحجم 5x/10x قبل الاختبار).
- الأهداف المقترحة قبل إعلان جاهزية إنتاجية: p95 < 500ms للقراءات، p95 < 2s لحساب مسير 500 موظف، معدل أخطاء < 0.5%.
- أي نتيجة مستقبلية يجب أن تذكر نفس أعمدة التوثيق أعلاه.
