# سياسة الخصوصية وحماية البيانات (وفق نظام حماية البيانات الشخصية السعودي PDPL)

> هذه الوثيقة توثيق تقني داخلي لحالة النظام، وليست شهادة امتثال قانونية. المراجعة النهائية لمستشار قانوني مختص مطلوبة قبل الاعتماد الرسمي.

## 1. أغراض المعالجة
يجمع النظام ويعالج بيانات الموظفين (الهوية، التعاقد، الرواتب، الحضور، الإجازات، الأداء) للأغراض التالية حصراً:
- إدارة شؤون الموظفين والرواتب وفق نظام العمل السعودي وأنظمة التأمينات الاجتماعية.
- الالتزامات الحكومية (التأمينات، قوى، الجوازات/الإقامات) — حالياً "قيد التطوير" بلا اتصال فعلي.
- تقارير إدارية داخلية ومؤشرات أداء.

## 2. أساس المعالجة
- تنفيذ عقد العمل والالتزامات النظامية المرتبطة به.
- لا يعتمد النظام حالياً على الموافقة كأساس، ولا يحتفظ بسجل موافقات (بند مفتوح).

## 3. الحقول الحساسة والحماية المطبقة
| الحقل | الحماية |
|---|---|
| رقم الهوية الوطنية | لا يُعاد في القوائم إلا لمن يملك صلاحية مالية/HR صريحة (`hr.employee.read.salary` أو `*`)، ويُقنَّع في كل التقارير تلقائياً |
| IBAN / الحساب البنكي / الراتب | مقنّعة دون الصلاحية المالية |
| رقم الإقامة / الجواز | مقنعان دون صلاحيات `expat.*` |
| كلمات المرور | bcrypt (cost 10–12)، لا تُسجّل أبداً |

- تسجيل الوصول: كل استجابة 401/403 تُسجَّل في `audit_logs` (المستخدم، المسار، IP، User-Agent).
- سجل التدقيق يغطي تسجيل الدخول/الخروج، تغيير كلمة المرور، الرواتب (حساب/مراجعة/اعتماد/دفع)، قرارات الإجازات، وتغييرات المستخدمين والأدوار.

## 4. الاحتفاظ والتصفية
- الحذف الناعم (`deletedAt`) للموظفين والمستخدمين مع إمكانية استعادة من مسؤول النظام.
- جلسات المستخدمين تنتهي بعد 12 ساعة، وسجلات الجلسات الملغاة محفوظة بغرض التدقيق.
- لا توجد سياسة تصفية آلية بعد (بند مفتوح — يتطلب قرار احتفاظ رسمي).

## 5. حقوق صاحب البيانات
القنوات المتاحة حالياً:
- الوصول/التصحيح: عبر إدارة HR (حسابات الموارد البشرية) أو مسؤول النظام.
- التصدير: مسارات التقارير مقيدة بصلاحيات، والتصدير الجماعي للحقول الحساسة محجوب دون صلاحية مالية.
- الحذف: حذف ناعم فقط حالياً؛ الحذف الكامل يتطلب مراجعة الاحتفاظ النظامي (سجلات الرواتب ملزمة نظامياً).

## 6. الأمان التقني
- TLS مفروض على الإنتاج (HSTS)، ترويسات أمان (CSP، X-Frame-Options، nosniff).
- JWT بكوكي HttpOnly/SameSite=Lax/Secure، مع `tokenVersion` لإبطال الجلسات عند تغيير الحساب.
- حماية login: قفل بعد 5 محاولات فاشلة + rate limit مخصص (10 محاولات/15 دقيقة).
- فحص Origin لكل طلبات الكتابة (دفاع CSRF)، وتقييد CORS بقائمة سماح صريحة.
- Socket.IO مصادق (JWT) وقنوات مقيدة بملكية المستخدم.

## 7. البنود المفتوحة (قيد التطوير)
- سجل موافقات صريحة عند الحاجة للموافقة كأساس معالجة.
- سياسة تصفية آلية (retention automation).
- تشفير على مستوى الحقول للحقول شديدة الحساسية (حالياً حماية بالصلاحيات والإخفاء فقط).
- تدوير مفاتيح التشفير/الأسرار عبر مخزن أسرار مركزي.

## 8. جهات الاتصال
- مسؤول النظام: عبر دور `sysadmin` داخل المنصة.
- طلبات صاحب البيانات: قناة رسمية من الشركة (تُوثق عند تحديدها).
